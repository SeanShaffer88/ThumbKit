# ThumbKit — Parity

What the brief asked for, and where each piece stands in v0.2.0. Status words: **Done** (implemented and test-covered), **Partial**, **Not done** (with the reason).

| Brief requirement | Status | Notes |
|---|---|---|
| Reusable thumbnail/preview pipeline as a DLL kit (WinDevKit family pattern) | Done | Rust, zero dependencies, `cdylib`+`rlib`+`staticlib`, handle-based C ABI (`th_create`/`th_close`), thread-local last error, caller-owned strings freed by `th_free_string`, JSON in/out with duplicate keys as parse errors. |
| Pluggable provider interface | Done | `th_register_provider(handle, extension_csv, generate_cb, user_data)`; callback signature documented exactly in the header; later registrations override earlier ones per extension; providers run on worker threads without the pipeline lock held. |
| Built-in providers | Done (scoped) | BMP 24/32-bit uncompressed and PPM P6/maxval 255: real decode, nearest-neighbour downscale (never upscale), 24-bit BMP output — all test-covered with hand-written fixtures. v0.2.0 adds built-in PNG and JPEG (next rows). |
| Built-in PNG decoder (v0.2.0 brief) | Done | From scratch on a from-scratch DEFLATE/zlib inflater (stored/fixed/dynamic blocks, hard output cap, Adler-32 verified; Python-zlib vectors incl. every-truncation-must-error tests). Color types 0/2/3/4/6, bit depths 1/2/4/8/16, all 5 filters, Adam7, multiple IDATs, tRNS parsed over (alpha dropped by design). Fixture tests per color type + embedded-byte-array PNG + all-filters roundtrip; development cross-check vs PIL was byte-exact on all variants tried. |
| Built-in JPEG decoder (v0.2.0 brief) | Done | Sequential SOF0/SOF1, 8-bit, Huffman entropy (multi-table DHT), 8/16-bit DQT, DRI restart intervals, grayscale + 3-component YCbCr/RGB, sampling 1..=4 per axis (4:4:4/4:2:2/4:4:0/4:2:0), float IDCT, nearest-neighbour chroma upsampling. Fixtures (4:2:0, 4:4:4, grayscale) assert pixels within ±8; an embedded-byte-array JPEG covers decode with no fixture file; development cross-check vs ffmpeg's decoder agreed within 4 units on every pixel, restart files included. |
| No fake thumbnails for undecodable formats | Done | GIF and unsupported variants return state `unsupported` with a message naming the remedy (register a provider). No placeholder or header-only output path exists. Progressive JPEG (SOF2) and 4-component CMYK are `unsupported` by name and test-proven (an SOF0→SOF2 marker rewrite must answer `unsupported`, not an image). |
| Async retrieval | Done | `th_request` returns a u64 id; bounded worker pool (default 2, `worker_count` 1–16) and bounded queue (default 64, `TH_ERR_QUEUE_FULL` when full); `th_poll` JSON status, `th_wait` with timeout/`TH_WAIT_INFINITE`, `th_cancel` for queued requests. |
| Bounded cache with invalidation | Done | SHA-256 (hand-rolled, known-vector tested) over canonical path + size + mtime + preset + provider name; `<key>.thumb` + `<key>.json` sidecar per entry; index rebuilt by scanning sidecars; changed sources miss automatically and leave orphans. |
| Eviction and sweeping | Done | LRU by sidecar `last_access`, enforced against `max_cache_bytes` and `max_entries` after each generation and on `th_sweep`, which also removes orphans and temp files and returns a JSON report. One documented exception: the just-generated entry is not evicted by its own pass. |
| Stats | Done | `th_stats` JSON: on-disk `entries`/`bytes` plus per-handle `hits`/`misses`/`evictions`. A second identical request is a proven hit (provider call count stays 1 in tests). |
| Predictable memory limits | Done | Decoders reject >100 MP or >256 MiB decoded RGB before allocating, with the cap named in the error; covered by direct and end-to-end oversize tests for BMP, and by header-rewrite oversize tests for PNG and JPEG (the cap error must win over truncation errors — the family safety-path rule). |
| Tests with synthetic fixtures | Done | 53 tests: hand-written BMP/PPM fixtures in temp dirs, generated PNG/JPEG fixtures in `tests/fixtures/`, downscale/never-upscale, cache hit, invalidation + sweep, LRU eviction, unsupported format, missing source, queue cancel, queue full, wait timeout, oversize rejection, config/preset rules, JSON and SHA-256 suites, FFI end-to-end, inflater vectors, PNG per-color-type + interlace + filters, JPEG sampling variants + progressive-refusal. |
| Docs | Done | Header documents every export and the built-in format scope; README (TL;DR, features, C example, build, tests, honest limitations, MIT); AGENTS.md, ROADMAP.md, QUALITY.md, this file; LICENSE copied from the family. |

## Deviations from the brief, stated plainly

- **Progressive JPEG and CMYK are not decoded.** The v0.2.0 brief scoped the JPEG decoder to sequential processes; SOF2/4-component files return `unsupported` with the reason named, never a partial or wrong image. Progressive support is ROADMAP item 1 with its condition stated.
- **The v0.1.0 "PNG as a separate provider kit" plan was superseded.** The v0.2.0 brief directed built-in decoders instead; PNG and JPEG landed in-core behind the existing built-in provider mechanism (a custom provider can still override either per extension). Recorded here and in ROADMAP.md so the change of plan is a decision, not drift.
- **Cancel is queued-only.** The brief asked for `th_cancel` for queued items; running providers are arbitrary host code and are not interrupted. `th_close` joins running work instead.
- **Cache-hit access-time updates rewrite the sidecar on every hit.** Simpler and crash-safe; a high-read workload pays one small file write per hit. Noted as a known cost, not hidden.
